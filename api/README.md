# Block Boom API — blockboomapi.amiraligrr.ir

## ⚠️ ترتیب مهم استقرار

اگر `start_run.php` را قبل از `submit_score.php` آپلود نکنی، اپ به مسیر
قدیمی می‌رود و همه‌چیز کار می‌کند ولی **ضدتقلب واقعی فعال نمی‌شود**.
پس این ترتیب را رعایت کن:

1. `init_db.sql` → بخش **MIGRATION** را روی دیتابیس فعال اجرا کن
2. `anticheat.php`، `db.php`، `config.php` (کتابخانه‌ها)
3. `start_run.php`
4. `submit_score.php`، `leaderboard.php`
5. بقیهٔ endpointها
6. `health.php` را چک کن که `healthy: true` بدهد

## نصب

1. پوشهٔ `api` را در `public_html/api` آپلود کن.
2. دیتابیس بساز و `init_db.sql` را اجرا کن. فایل دو بخش دارد:
   - بالای فایل: اسکیما برای نصب تازه
   - پایین فایل: بخش `MIGRATION` برای دیتابیسی که از قبل نصب بوده
     (ستون‌های `banned`، `score_rate`، جدول‌های `run_tokens` و
     `cheat_flags`، و اصلاح قیمت‌های اشتباه خرید)
3. کلیدها را بساز:
   ```bash
   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"   # کلید ضدتقلب
   php -r "echo bin2hex(random_bytes(24)), PHP_EOL;"   # کلید اعلان‌ها
   ```
   آن‌ها را در متغیرهای محیطی بگذار (نمونه در `.env.example`):
   ```
   BB_RUN_TOKEN_SECRET=...
   BB_ADMIN_API_KEY=...
   BB_DB_PASS=...
   ```
   یا موقتاً داخل `config.php` بنویس. **مهم:** `RUN_TOKEN_SECRET` هرگز
   نباید داخل اپلیکیشن برود.

4. تست:
   ```bash
   curl https://blockboomapi.amiraligrr.ir/health.php
   # باید "healthy": true بدهد. اگر runToken:false بود، هنوز
   # BB_RUN_TOKEN_SECRET را تنظیم نکرده‌ای.
   ```

## ضدتقلب چطور کار می‌کند

کلید اشتراکی دیگری وجود ندارد. قبلاً `HMAC_SECRET` داخل APK کامپایل می‌شد،
پس هر کسی که فایل را باز می‌کرد کلید را می‌داشت و می‌توانست هر امتیازی
بسازد. حالا:

| لایه | چه کار می‌کند |
|---|---|
| **توکن اجرا** | `start_run.php` یک توکن امضاشده با کلید سمت سرور می‌دهد. کلید از سرور خارج نمی‌شود، پس جعل توکن ممکن نیست. |
| **یک‌بارمصرف** | هر توکن فقط یک‌بار قابل استفاده است؛ ارسال دوباره `replay` می‌گیرد. |
| **ساعت سرور** | مدت بازی از اختلاف زمان سرور حساب می‌شود، نه از ساعت گوشی. |
| **سقف واقعی** | `bb_max_level_score()` فرمول واقعی موتور بازی را آینه می‌کند: تعداد بلاک × HP × (شکستن بلاک = ۲ برابر) + باس. |
| **سقف نرخ** | امتیاز قابل قبول = کفِ «یک‌بار تمام لول‌ها» + `زمان بازی تأییدشده × ۳۵۰۰`. چون زمان فقط با توکن معتبر جلو می‌رود، بالا بردن امتیاز یعنی واقعاً بازی کردن. |
| **پایداری** | سطح کم و امتیاز کم نمی‌شود. |
| **ثبت لاگ** | هر رد شدن در `cheat_flags` ثبت می‌شود و در پنل دیده می‌شود. |

### چرا قانون قبلی اشتباه بود

`score > level*6000 + 5000` فرمول امتیاز این بازی نیست. یک بازیکن
واقعی از **لول ۴۳** به بعد برای همیشه رد می‌شد با خطای
`Score too high for level` — همان خطایی که بازیکنان می‌دیدند.

### چقدر ضدتقلب است؟

صددرصد نیست و نمی‌تواند باشد: هر بازی سمت کلاینت، هکری که بخواهد
می‌تواند امتیاز خودش را در برنامه عوض کند. چیزی که عوض شده این است که
تقلب از «باز کردن APK و یک خط HMAC زدن» به «نوشتن رباتی که باید واقعاً
و در زمان واقعی بازی کند» تبدیل شده. برای یک بازی موبایل رایگان همین
سطح، عملی است.

## endpointها

| فایل | کار |
|---|---|
| `start_run.php` | صدور توکن اجرای بازی |
| `submit_score.php` | ثبت امتیاز با اعتبارسنجی کامل |
| `leaderboard.php` | لیدربرد با صفحه‌بندی و فیلتر دوره |
| `health.php` | وضعیت پیکربندی (بدون افشای راز) |
| `ad_event.php` | رویداد تبلیغات — **تأیید هویت ندارد**، فقط rate limit |
| `claim_coins.php` | برداشت سکه‌های ثبت‌شده توسط سرور |
| `referral.php` | کد دعوت |
| `notifications.php` | ساخت اعلان (نیازمند `ADMIN_API_KEY`) |
| `fetch_notifications.php` | دریافت اعلان‌های یک دستگاه |
| `anticheat.php` | **کتابخانه** — نباید مستقیم صدا زده شود |
| `config.php` / `db.php` | **کتابخانه** — نباید مستقیم صدا زده شوند |

## نکته دربارهٔ `ad_event.php`

رویدادهای تبلیغات **احراز هویت ندارند**. قبلاً HMAC داشتند ولی کلیدش داخل
APK بود، پس عملاً هیچ محافظتی نمی‌کرد و فقط این حس را می‌داد که محافظت
هست. آن برداشته شد و به‌جایش rate limit واقعی (هر دستگاه و هر آی‌پی) و
سقف روزانه گذاشته شد. اعداد پنل تبلیغات را به‌عنوان شاخص جهت‌دار بخوان،
نه عدد دقیق.

## اندروید

- هیچ رازی در `build.gradle.kts` نیست. عمداً حذف شده.
- `RunSessionManager` قبل از هر اجرا توکن می‌گیرد؛ اگر نشد، بازی عادی
  ادامه پیدا می‌کند و امتیاز از مسیر قدیمی می‌رود.
- `GameEngine.addScore()` همهٔ تغییرات امتیاز را ثبت می‌کند، پس زنجیرهٔ
  هش رویدادها با امتیازی که ارسال می‌شود هم‌خوان است.
